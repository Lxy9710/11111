日期：2026-11-02。状态：单案例数据试点已实现；经讨论已将 **T2 定为主任务**，并在 [chainmodel](../chainmodel/README.md) 实现首版模型、训练、推理和人工监督接口。已运行单案例烟雾训练，不代表已获得可用工艺规划能力或泛化性能。

最新架构调整见第 11 节：大小模型协同、独立记忆与寻址为主线，原 GRU 实现保留为对照；Qwen 目前仅占位。前文保留研究方案的演进背景，当前实现以 [混合架构说明](../chainmodel/docs/hybrid-architecture.md) 为准。

## 1. 研究定位

继承 ProcessCAD 的 CAD 提取、实体—特征表示、参数引擎及历史工艺数据，但不将旧 GNN 检索或 memory 存储作为新论文的主要贡献。

新问题是：从设计图中的特征和要求出发，生成有对象指针、阶段状态和来源证据的工艺关联图，并支持设计变更后的影响定位。

必须区分三个不同任务：

1. **T1 关联生成（辅助诊断/消融）**：输入设计图 D、给定工序路线 O 及允许使用的制造背景 K，预测特征、要求、阶段参数及跨工序来源关系。路线不是本任务预测目标。
2. **T2 链条联合生成（主任务）**：输入 D、K，预测候选路线 O 与关联图。单图通常不能唯一确定路线，评价允许多个有效方案；不得声称恢复唯一真实工艺历史。
3. **T3 变更影响（后续）**：输入旧图 A、已知旧规划及关联图、新图 B，预测特征对应、要求变化和需更新的工序/参数。必须有独立的 A/B 对及影响审核标签。

当前数据可以验证 T2 的数据管线、反向传播和自由生成接口；单案例弱监督不能支撑 T2 泛化性能或 T3 变更影响的定量结论。人工标注按字段分层补充。

## 3. 数据表示及语义边界

### 3.1 节点

| kind | 对象 | 关键字段 |
|---|---|---|
| feature_seed | 设计参数锚点 | case-local ID、parameter_key、geometry_handles、annotation_handles |
| design_requirement | 有证据的尺寸要求候选 | predicate、finished-only scope、来源 |
| annotation_evidence | 原始尺寸标注 | handle、原始 CAD 实体 |
| document_evidence | 材料、技术要求原文 | text、原始实体引用、尚未解释的状态 |
| operation | 路线中的工序实例 | process_no、route_index、canonical_name、生成状态 |
| parameter_state | 某工序记录的一项计划参数 | operation_id、feature_id、原始数值、角色、实际 source_type |
| rule_evidence | 本次引擎选用规则的快照 | 参数定义、加工部位、查表选择信息 |
| process_context | 生成上下文 | 材料/磨削循环、精度、精研等条件及回退诊断 |
| external_source | 已命名但未定位的来源 | source_process、source_parameter、缺口原因 |

`D207NQ.01:groove_diameter`、`groove_radius`、`groove_position` 现在是不同参数锚点，不能当成三个已经确认的物理沟道特征。正式标注需将物理身份 F 与参数/属性角色 a 分开，使用状态键 `(case, version, feature, operation, attribute)`。

### 3.2 边

- `anchored_by / supported_by / constrains`：特征、要求与原图证据。
- `records_parameter`：某工序记录该参数；不等于加工或产生了该几何。
- `parameter_of`：按已核查的外圈参数符号建立角色候选关联。
- `copies_parameter_from`：数值来源指针，消费者指向最近且数值吻合的前序同名工序参数。
- `external_parameter_source`：来源已命名，但不能定位为前序工序实例。
- `reads_design_value`：引擎读取的主要设计参数；计算型记录不代表已捕获所有公式输入。
- `copies_finished_requirement`：仅对实际运行返回 `product_drawing` 且设计证据一致、区间检查通过的记录建立。
- `resolved_under_rule / generated_in_context / declared_lookup_key`：规则和上下文引用；不是完整执行轨迹，更不是物理因果证明。
- `route_next`：工序表顺序。
- `next_recorded_state`：同一参数角色的记录顺序；不是参数复制、加工转换或充分的因果依赖。
- `document_context`：保留原文背景，不自动推断其对具体工序的作用。

来源统一采用 `{artifact, pointer}`，例如指向 `process_parameters.json` 内的 `/processes/6/parameters/D`。生成时逐项解析 JSON Pointer，检测断引用。配套 provenance 保存原文件哈希。handle/ID 是回溯键，不应作为可学习语义特征。

### 3.3 不允许悄悄补齐的内容

1. 全部 `geometry_handles` 尚空；不能将 `default` 分组或参数名称当作人工几何组。
2. 平面尺寸缺解析公差、沟道半径缺唯一 handle，不能从引擎默认值反向补成设计真值。
3. 原引擎直接值字段有显示单位约定差异，例如 `Ra`；保留原字段并将直接值单位标为未核验，不能统一写成 mm。
4. `requires_inspection` 是规则中的要求，不证明对应检验工序实际执行或检测合格。
5. 当前规则查表通常只有表值/文字证据，尚无全量单元格路径和逐步计算依赖。
6. 13 道无参数工序不等于无影响，装夹、热处理、检验等作用不能由空记录推断。
7. 所有自动边均不是专家真值。审核队列中的 `decision` 是人工填写区，本版没有自动将审核表合并为 gold 标签的导入器。

## 4. 模型主线：特征锚定的双记忆、多角色指针关联生成

暂名 **FARM-CAD：Feature-Anchored Relational Memory for CAD Process Chains**。名称仅用于讨论，不表示已完成文献新颖性验证。

研究假设：相比整图向量检索、逐序独立分类和相邻工序传播，分离稳定设计身份与动态工序状态，并显式学习对象、要求、来源指针，可以减少长距离关联丢失和“引用=加工”的混淆。

```text
设计图实体 + 尺寸/技术要求
            |
结构编码 + 文本编码（旧 CAD 表示可复用）
            |
特征集合解析与证据绑定
            |
稳定锚点记忆 M_D = {特征、属性、要求、证据}
            |                         给定路线/候选工序
            +-----------------------------+
                                          |
                              多角色指针解码器
                                          |
                 对象指针 / 要求指针 / 前序来源指针
                                          |
                        角色与状态更新操作预测
                                          |
                  动态状态记忆 M_S(<t) 追加记录
                                          |
                       合法性掩码 + 确定性计算
                                          |
                  可追溯的工艺关联图与不确定性
```

### 4.1 结构与语义编码

保留节点级表示，不把所有信息过早池化成整图向量：

- 实体结构编码器：类型、连接、相对坐标、尺度、曲率等。初始可用旧边感知骨干，需更新维度和输入，不能承诺旧 checkpoint 直接兼容。
- 标注编码器：名义值、偏差、单位、标注类型、端点/引线位置；图区几何 measurement 与标注值分开保存。
- 文本编码器：技术要求原文与语义，初期冻结本地预训练模型；文字已存在时不让视觉模型重复读数。
- 特征查询：预测实体成员、物理特征类别和属性槽；训练时做集合匹配，允许无对象查询。共享标注通过关系连接，不强制唯一归组。

VLM 为可选局部视觉分支，只有结构化提取无法保留符号/布局时再纳入。对比应保证相同人工标注预算；主贡献不能依赖“增加一个大模型”。

### 4.2 稳定身份与阶段状态分离

稳定记忆：

`M_D = {h_feature, h_attribute, h_requirement, h_evidence}`。

动态记忆：

`M_S(<t) = {s_(f,a,k) | k < t}`，每个状态保存对象/属性指针、数值、单位、来源、操作角色和创建阶段。

不覆盖历史记录。可维护每个 `(f,a)` 的最新状态索引加速读取，但完整历史仍保留，支持指向更早的基准或来源。不同属性、不同工序记录不混成一个 feature 向量。

长链访问依靠直接寻址，不靠堆叠 30 层 GNN。保存全部状态的注意力初版开销约随路线和状态总量乘积增长；必须报告时间、显存和长度曲线，不能只报告准确率。更大规模时再评价候选检索和稀疏读取，并报告候选召回率。

### 4.3 多角色指针与结构化解码

每道工序预测记录集合：

`Y_t = {operation_role, feature_ptrs, attribute_ptrs, requirement_ptrs, source_state_ptrs, update_operator, argument_ptrs, uncertainty}`。

不同指针头采用不同候选池：

- 对象/属性指针访问设计锚点；
- 要求/证据指针访问原图要求与证据；
- 来源状态指针只访问已存在阶段；
- 规则参数指针访问允许公开给模型的规范知识。

指针评分的起始形式可为：

`score_r(i,t) = (Wq_r q_t)^T (Wk_r m_i) / sqrt(d) + b_r(delta_stage, attribute_role)`。

使用不同关系角色的 query/key 投影及阶段距离信息；ID 数字本身不进评分。对多个作用对象使用集合预测或多标签选择，不能每序只输出一个指针。

区分两个特殊输出：

- `NONE`：人工确认不存在该关系；
- `UNKNOWN/EXTERNAL`：证据不足或来源在当前候选池外。

缺失标注不能转成 NONE 负例。无法定位的车加工来源应保留 EXTERNAL；允许引用既有稳定设计要求，但不能引用未生成的真实未来工序状态。

角色初版：`machining_target / reference_copy / derived_parameter / inspection_target / datum_use / unknown`。这些不是互斥的同一层标签：来源类型与工序作用分别预测，允许“加工目标且由留量派生”。当前数据只能弱监督其中部分来源关系和加工候选。

### 4.4 状态更新与计算

将选择和运算分开：

- 学习：采用哪个要求、哪些前序状态、什么规范项，以及 copy/lookup/allowance 等更新操作；
- 确定性执行：复制、单位转换、区间运算和经确认规则的留量计算；
- 未覆盖操作：明确 UNKNOWN，不用自由公式或任意可执行代码补齐。

工序影响图需要同时包含数据来源边、加工转换边和条件依赖边。当前整理器主要输出第一类及候选关系，不能将其直接重命名成完整因果图。

### 4.5 两级一致性

局部：指针类型正确、来源阶段合法、单位兼容、对象角色兼容、参数运算可执行。

全链：设计对象身份一致、前序状态引用无环、要求在明确适用阶段检查、最终状态是否覆盖已标注的成品要求。中间粗磨不必满足成品公差。

条件可达性只产生“可能受影响”的候选集合；变更是否真正触发参数或工艺更新需要重新评价规则及状态，不能将所有可达工序都标为必须修改。

## 5. 标签与训练计划

### 5.1 标签分层

| 层级 | 来源 | 使用 |
|---|---|---|
| gold | 双人标注与工程师仲裁 | 验证/测试及主要监督 |
| silver | 来源可核验的系统生成关系，经抽查 | 预训练/辅助监督，单独标权重 |
| candidate | 参数角色、加工部位启发、未完整依赖 | 标注建议，不能直接用作确定标签 |
| unknown | 缺失几何、单位、工序来源等 | 损失掩码及拒绝输出评价 |

当前 28 条复制边的程序核验不等于人工确认，可作为银标候选。127 条待审核任务不等于 127 个样本。

### 5.2 阶段 A：数据闭环与关联任务基线

先补 4-6 张代表图做 schema 校准：几何相近但要求不同、重复规范工序名、来源跨多序、无参数工序、不同材料/循环条件。不是固定发表样本阈值。

人工首先确认：

1. 物理特征身份与几何成员，并把沟径/沟位/沟半径归到正确物理特征属性；
2. 设计要求与证据的绑定、缺失偏差及适用范围；
3. 引用与实际加工的区别，复制来源的真实工序实例；
4. 表格来源、单位、公式所有输入、基准和检验关系；
5. 工序中没有记录的状态属于“未知”还是“未变化”。

单张 D207NQ.01 只用于显式标记的 smoke 管线训练，不伪造独立验证/测试集合，也不训练出可宣称泛化的模型。

### 5.3 阶段 B：分组与证据绑定预训练

旧 GNN 数据中的人工特征组可作为来源，但应审查数据版本和标签定义。输入移除 group/GlobalID/加工 Flag 等答案字段，作为预测监督保留。

用实体成员集合损失、特征类别损失和证据指针损失学习对象锚点。冻结/微调旧结构骨干与从头训练进行公平对照。不能默认旧图级对比学习能解决局部实例对齐。

### 5.4 阶段 C：T2 路线与关联联合生成

主任务 T2 不把真实工序名称、顺序作为输入，而以 `OP / PARAM / END_OP / EOS` 事件流联合生成路线、来源指针、角色和状态更新。训练初期 teacher forcing，只在预测当前事件之后将其加入历史；测试使用真实 rollout，不能读取 gold 历史。后续再研究滚动训练；T1 可作为诊断消融。

概念性损失：

`L = lambda_group L_group + lambda_bind L_bind + lambda_role L_role + lambda_ptr L_ptr + lambda_update L_update + lambda_cons L_cons`。

- `L_group`：集合匹配后的成员 BCE/Dice 与类型损失；成员缺失时掩码。
- `L_bind`：特征—标注/要求绑定的集合损失。
- `L_role`：作用角色及来源类型的分头分类/多标签损失。
- `L_ptr`：候选池内引用选择损失；多个合理等价来源按标注集合处理，不强制错误的唯一目标。
- `L_update`：copy、lookup、allowance 等操作选择与参数槽监督，不优先做黑箱尺寸回归。
- `L_cons`：对可微逻辑项施加类型、顺序等一致性约束；硬求解器先用于掩码、重排与评估，不能把不可微结果直接当普通梯度。

弱标签损失乘明确来源权重且只在已知项计算。权重和阈值通过独立验证集选择，不从测试集调参。

初始规模建议而非已验证配置：隐藏维度 128/256、3-4 层结构编码器、2-4 层解码器、4 个注意力头、冻结文本编码器、dropout 0.1；AdamW，新增模块学习率 1e-4 起试，解冻骨干使用更小学习率，梯度裁剪。按整张图/整条链组 batch，按显存使用梯度累积。先报告学习曲线再扩大模型，不照搬旧模型的深层数或固定 500 epoch。

### 5.5 阶段 D：变更一致性与路线约束增强

在 T2 基础模型与人工标注数据建立后进一步开展：

- T3：相同物理对象跨 A/B 的匹配，要求变化引起状态更新的局部性，未受影响部分保持不变。
- 受控变更须同步保持标注、参数与几何自洽；需审核哪些工序确实受影响。系统生成响应只能作辅助信号，不能自证模型正确。
- T2 增强：在已有事件序列生成上增加工序优先关系约束和等价路线评价。工序集合和顺序分别评价，合法等价路线不应被单一字符串匹配全部判错。
- 暂不引入大规模强化学习。先建立独立正确性判断；求解器奖励通过不等于制造合理，尤其需防止复制成品尺寸到所有阶段、过度连接所有工序等投机解。

## 6. 严格区分推理输入与监督答案

| 信息 | T2 主实验输入 | 监督/审核使用 |
|---|---|---|
| 原始图实体、文字、标注 | 是 | 是 |
| 真实路线名称与顺序 | 否 | 是 |
| 材料、精度及部署时可用制造条件 | 是 | 是 |
| 人工 feature group/GlobalID | 否；仅 oracle 上限实验可用 | 是 |
| 待预测工序的 `copied_from_process`、evidence、目标参数 | 否 | 是 |
| 系统生成的目标关联图、source_paths | 否 | 是 |
| 真实未来工序参数状态 | 否 | 是 |
| 人工确认不存在关联 | 不作为答案输入 | 可监督 NONE |

如果把完整规则中的 `copy_from` 直接输入模型，来源指针可通过查表得到。这种设置必须单独命名为“知识可见的规则执行/抽取”，与规则直接执行基线比较，不能当成隐式长链推理能力。

建议主实验隐藏案例级解析结果和直接给出答案的关系字段；提供哪些公开规范信息应固定并记录。关系生成难度不同的设置分开报告。

按零件/图纸族进行 train/validation/test 划分；同零件的设计图、工序图、人工/系统版本、A/B 修改对及增强样本属于同一 split。检索库也遵守划分。先划分再生成训练增强和检索索引。

## 7. 评价与消融

主指标：

- 物理特征成员 IoU/实例 F1、特征类型 macro-F1；
- 要求—对象—证据集合 F1；
- 工序作用角色与参数来源类型分别报告 macro-F1；
- 来源指针准确率/集合 F1，分别报告可解析来源、EXTERNAL、UNKNOWN；
- 端到端关联元组 `(feature, attribute, requirement, operation, source_state, role)` 的精确匹配/F1；
- 多跳来源路径正确率、来源遗漏率和无依据关联率；
- 按路线跨度 1、2-4、5-9、>=10 分桶报告指针表现及样本数；
- 参数值/单位/来源分别评价，不把计算正确率充当意图正确率；
- gold 历史与预测历史 rollout 的误差差距，逐序错误累积；
- 不确定性校准、风险—覆盖率曲线；拒绝率不能被用来隐藏低覆盖；
- T3 独立报告需重算、需改路线、仅更新引用、无影响的分类及影响范围精确率/召回率。

按独立零件或图纸族做置信区间/重采样，不把同图 104 条参数当独立样本。最终样本量和实验有效性取决于独立案例、多样性及区间宽度，而非达到一个特征计数就足够。

必要对照：

1. 确定性规则/来源字段解析：当前数据整理器可作为该基线，但输入必须与学习模型的设定清楚区分。
2. 旧整图检索 + 模板关联迁移。
3. 同预算局部 GNN/逐序分类，无跨阶段记忆。
4. 同预算序列模型，生成扁平标签/编号，无类型化对象指针。
5. 新模型从头训练与旧预训练迁移。

必要消融：

- 移除稳定设计锚点；
- 将完整阶段记忆压成最新状态或单向量；
- 指针限制为相邻/固定窗口，比较长跨度损失；
- 不区分引用与加工；
- 去掉要求证据分支、关系类型掩码或一致性校验；
- 不使用工艺银标辅助；
- 人工分组 oracle 与预测分组端到端；
- 结构+文本与再加入 VLM 的增量收益、成本。

## 8. 论文贡献的候选表述与边界

候选贡献应集中在：

1. **任务与数据表示**：区分特征身份、参数状态、要求作用范围和来源关系的可追溯工艺链任务，以及人工审核的数据协议。
2. **模型机制**：稳定锚点/动态状态双记忆与多角色指针，在同一模型中区分引用、派生、加工及要求实现。
3. **学习与验证**：来源可追溯的分层监督、长链 rollout 和设计变化一致性评价。

指针网络、GNN、memory 或多模态拼接本身不是新发明。需针对图到序列、动态记忆、工艺规划和来源追踪做进一步文献核查，不能预先保证组合具有新颖性。

与用户提供的 *Aligning Constraint Generation with Design Intent in Parametric CAD* 的联系：借鉴对象引用和执行反馈。区别是该文针对单草图内部约束及求解器对齐，本方案研究跨工序对象/状态/要求的关联生成。约束求解成功不是完整设计意图真值；同理，工艺引擎通过也不等于预测链条正确。
