1. 本批任务的目标
只做数据梳理和框架确认，不写模型代码。 具体三件事：

任务 A：基于 ProcessCAD 项目已有数据，梳理出“设计图 → 加工参数 → 意图”的对应关系；

任务 B：盘点这些对应关系里，哪些意图有足够数据支撑、哪些没有；

任务 C：确认技术框架的四个模块边界和数据接口。

2. 任务 A：梳理“设计图 → 加工参数 → 意图”对应关系
2.1 背景
ProcessCAD 项目已经能生成设计图对应的加工参数（工序、刀具、切削参数等），只是“生成”和“意图”之间还没有建立映射。你现在要做的是：把已有的“图 → 参数”结果，和意图标签对应起来。

2.2 具体做什么
对 ProcessCAD 能处理的每一个工业案例：

输入侧：提取该案例的设计图特征组（feature group），包括图元、尺寸、公差/配合标注、粗糙度、基准、技术说明文本；

参数侧：提取 ProcessCAD 已生成的工序序列、每序的操作类型、加工参数（如有）；

工艺卡侧：提取该案例的工艺卡文本，按特征对齐；

建立映射：对每个特征，尝试建立三元组 (特征, 加工参数/工序, 意图证据)。

2.3 意图候选集（初版，需用数据验证）
先围绕以下 6 个可验证意图做映射，不要求全部有数据，先统计覆盖率：

意图类型	谓词形式（初版）	期望的证据来源
fit_hole（配合孔）	配合间隙 ∈ [下限, 上限]；同轴度 ≤ t	H7/g6 等配合标注、粗糙度、工艺卡“铰/磨”
wall_thickness（壁厚保持）	孔壁到外轮廓最小距离 ≥ t	几何 + 工艺卡“保证壁厚”
symmetry（对称保持）	左右/上下特征关于轴线对称距离 ≤ ε	几何 + 对称标注
datum_chain（基准链保持）	修改后基准仍可追溯、基准链不断裂	基准标注（A/B/C）
tool_accessibility（刀具可达）	倒角角/深、槽宽在刀具可达范围内	几何 + 工艺卡刀具信息
tolerance_keep（公差等级保持）	修改后尺寸仍在原公差带内	尺寸公差标注
2.4 任务 A 的交付物
一张特征级映射表（CSV/JSON）：每行一个特征，列包括 case_id, feature_id, feature_type, geometry_summary, params_generated, process_ops, intent_labels, evidence_sources, confidence；

一份覆盖率统计：每个意图类型有多少特征有证据、证据来源分布（标注/文本/跨工序）；

一份问题清单：哪些特征无法映射（缺标注、工艺卡对不上、参数缺失），为什么。

3. 任务 B：意图数据支撑度盘点
3.1 具体做什么
基于任务 A 的映射表，回答：

每个意图类别的特征级样本数是多少？（按特征计数，不按案例计数）

每个意图类别的证据覆盖率是多少？（有标注/有文本/有跨工序证据的比例）

数据质量问题：缺失标注比例、标注格式不一致的案例、几何与标注对不上的案例。

3.2 任务 B 的交付物
一张“意图类型 × 数据支撑度”矩阵：行是 6 个意图，列是样本数、证据覆盖率、主要证据来源、数据质量问题数；

明确结论：哪些意图可以进入定量评估（建议阈值：样本 ≥30 且证据覆盖率 ≥50%），哪些要降级为案例研究或排除。

4. 任务 C：确认技术框架的四个模块和数据接口
4.1 框架总览（确认边界，不实现）
整个新能力分四个模块：

text
模块 1：几何变更检测 ΔG
  输入：D0, D1
  输出：add/delete/modify 的实体和特征级差异（JSON）

模块 2：意图归因 ΔI
  输入：几何变更 + 制造语义标注 + 工艺卡文本
  输出：每个变更的意图谓词 + 证据（JSON）

模块 3：工序波及分析 ΔP
  输入：ΔI + 旧工艺规划 P0
  输出：受影响的工序步骤 + 受影响意图 + 影响类型（JSON）

模块 4：意图冲突与全局复核
  输入：ΔI + ΔP + P0 已有意图
  输出：冲突列表 + 需复核工序 + 意图风险（JSON）
4.2 本批要确认的接口
不要求实现模块，但要求确认数据接口：

模块 1 的输出 schema（变更的 JSON 结构）能否从现有 ProcessCAD 数据里算出来？需要哪些字段？

模块 2 的输入是否齐全（几何 + 标注 + 工艺卡文本能否按特征对齐）？

模块 3 需要的“意图类型 → 工序类型”映射表，现有工艺卡数据能否支撑（即：能不能从工艺卡里统计出“配合孔 → 精铰/磨”这种关联）？

模块 4 需要的“已有意图”从哪来（是否已有标注，或需要从 P0 反推）？

4.3 任务 C 的交付物
一份模块接口确认文档：每个模块的输入/输出字段、数据来源、当前是否可得、缺失项；

一张“意图类型 → 工序类型”候选映射表（从工艺卡统计得出，不是拍脑袋），作为模块 3 的初版知识。

5. 本批不做的事（明确边界）
不写意图解析模型代码；

不写变更检测算法代码；

不假设所有意图都有数据支撑——先统计，再决定；

不输出自由文本意图描述——只做结构化映射和统计。

6. 后续批次预告（让 agent 知道全局，不要求现在做）
第二批：意图谓词的可计算实现 + 单元测试（每个谓词一个函数，正反例验证）；

第三批：意图标注 pilot（抽 200–300 个特征人工标注，算 kappa，定哪些意图可做定量评估）；

第四批：几何变更检测模块实现；

第五批：意图归因模块（规则 + LLM + 跨工序）实现；

第六批：工序波及分析模块 + 意图-工序映射表落地；

第七批：端到端集成 + 评估（三元组匹配率、人工评估）。

7. 给 agent 的启动指令（可直接复制）
请先完成任务 A 和任务 B，不要写模型代码。具体：

遍历 ProcessCAD 项目数据目录，对每个工业案例提取设计图特征组（图元、尺寸、公差/配合、粗糙度、基准、技术说明）和已生成的工序/参数/工艺卡文本；

按第 2.3 节的 6 个意图候选，对每个特征尝试建立 (特征, 加工参数/工序, 意图证据) 三元组；

输出特征级映射表（CSV/JSON）和覆盖率统计；

输出“意图类型 × 数据支撑度”矩阵，并给出哪些意图可做定量评估、哪些需降级/排除的结论；

同时输出模块接口确认文档（第 4.3 节），说明四个模块的输入/输出在当前数据下是否可得。
先做数据盘点和统计，遇到字段缺失或对不齐的情况，列在问题清单里，不要自行补数据。
