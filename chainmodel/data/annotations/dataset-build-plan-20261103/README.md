# IntentCAD 数据集构建计划与填写说明

日期：2026-11-03。研究数据基线：`outer-batch-v2`。上游系统仅使用 `20260917/smartCAD/CAD_Process_Hub`。

**主文件：[数据集构建计划与填写表.xlsx](IntentCAD_数据集构建计划与填写表.xlsx)。**

本文件是后续构建计划，不代表完整 RAG 流程、新语义标签或规划经验库已经实现。
现有数据仍是：39 张图纸完成盘点；7 份外圈输入；1 份 D207 系统弱标目标；人工 gold 为 0。
5/1/1 是已同意的设计预留划分，可加载数据对仍为 1/0/0。

## 一、你先填什么

打开工作簿的 **03_本轮确认**，填写黄色单元格。蓝灰色单元格是已有事实或系统建议，不是人工确认结果。

| 优先级 | 事项 | 你要填写什么 | 不知道时如何处理 |
|---|---|---|---|
| 对应图生成前 | 3D1000095X3.01 的精度 | 正确等级，以及图纸/规范位置或其他依据 | 写“待查”，不要采用系统默认 D；不阻塞其他图 |
| 对应图生成前 | E207 外圈 JP 身份 | 文件名不带 JP、图内带 JP 是否为同一有效版本；填写正确图号/版本 | 写“待确认”，只隔离该图 |
| 正式划分前 | 物理家族与变体关系 | 确认或纠正暂定家族；D207/E207 是否应同组；是否还有跨组变体 | 保留预留状态，不发布正式测试指标 |
| 仅在存在特殊限制时 | 毛坯、工艺路线和规范要求 | 已知且图纸/规则未说明的约束；已有工序卡可给路径，但不是必交材料 | 留空表示“未提供额外信息”，不是“无约束” |
| 第一轮意图候选审核前 | 意图范围 | 是否先以可证据化的制造语义为主；若包含定位/密封等功能，注明可用依据 | 不从外形强行推断未被支持的功能 |
| 开展变更实验前 | A/B 案例来源 | 有真实案例则登记；无真实案例可注明“暂无”，再决定合成变更范围 | 不影响当前非变更数据构建 |

不要求你现在填写七张图的全部路线、加工参数、实体 handle 或所有语义标签。
选填材料可以是文件路径、任务 ID、规范章节或图片位置；**不要在工作簿填写密码、API key 或其他凭据**。

## 二、构建计划与责任分工

“我”指负责实现与运行的助手/后续接手 agent；“你”指用户或工程审核人员。
自动产生的候选需要保留来源和质量，不因运行成功就成为 gold。

| 编号 | 工作项 | 我负责自动完成/开发 | 你负责什么 | 输出及验收 |
|---|---|---|---|---|
| P01 | 固定现有数据与来源 | 复用39图库存、7份输入、原文件哈希；隔离新版本 | 已知文件更新时指出 | 原图和 v2 不变；新输出使用新版本目录 |
| P02 | 检查生产运行环境 | 检查 GNN、模板、规则索引、embedding、受控 LLM 服务及 CAD；必要时重建缓存 | 仅在服务或资产确实不可访问时协助定位 | 明确服务可用性和缺项；不向未经确认的外部服务发送图纸 |
| P03 | 确认必要上下文 | 从图纸和规则预填材料、精度与身份；只上报无法确定项 | 填03表中的精度、JP及少量工程条件 | 未知项显式保留；按图隔离，不扩大为全批次阻塞 |
| P04 | 生成候选路线 | 检索参考工艺，结合规则拟定有序工序；实现候选清单接入；记录选择依据 | 在候选出现后确认、修改或驳回；无需从零写全部路线 | 具有来源、适用条件和重复工序实例的候选；相似模板不直接冒充真值 |
| P05 | 跑完整生产流程 | 传入经确认清单；执行工序图参数、RAG字段决议、写回及阶段校验 | 只处理被上报的工程歧义/规则冲突 | 工作JSON、参数结果、规则证据、修改前后值和实际成功/失败项 |
| P06 | 生成对象与成员候选 | 结合尺寸锚点、几何关系、模板与写回实体生成分组候选；建立对象ID映射 | 审核歧义及完整性；修正漏标或合并错误 | 分组有证据；不把部分集合当完整负例监督；跨图handle不直接等同 |
| P07 | 生成意图及对齐候选 | 将设计要求、规范条件、工序选择及决议转为制造意图候选，绑定对象和证据 | 确认语义与证据是否相符；补确有依据的功能信息 | 区分显式要求、规则推导、模型推断及未知；无证据时不强填 |
| P08 | 记录跨工序状态 | 采集参数复制、查表、计算、更新与实体变更；解析前序实例和对象连续对应 | 审核不确定的对象对应、加工/引用/检测角色 | 无未来来源；复制或检测不自动覆盖加工状态；保留未解析关系 |
| P09 | 构造工具决策轨迹 | 从检索、结构化决议、工具写回与校验中提取可观察轨迹，适配研究协议 | 审核关键决策和失败处理是否合理 | 请求、证据、决策、执行及反馈可追溯；流水线日志不直接冒充完整agent专家轨迹 |
| P10 | 扩展数据协议并导出 | 增加物理对象、意图证据、对应关系及轨迹的版本化结构；编写转换和校验 | 不用手写模型JSON | 输入/目标隔离，证据可定位；不直接向现有白名单添加不支持字段 |
| P11 | 构造设计变更对（后续） | 在约定范围内生成受控变更，重跑流程并记录影响；真实/合成分别标记 | 提供已有真实A/B或变更单；确认合成变更的工程有效性 | A/B及其派生数据同组；不以合成数据冒充真实变更评估 |
| P12 | 审核与正式划分 | 汇总审核队列、检测重复/同族泄漏、仅提升实际审核字段质量 | 确认族关系；独立审核验证/测试关键真值 | 冻结划分与评价范围；未知不作负例；不使用同一生成器自判作为唯一真值 |
| P13 | 验证发布与交接 | 校验引用、时序、单位、统计、哈希和模型可加载性；发布新清单和报告 | 签认工程审核范围，不必审核技术日志全部细节 | 明确各集合就绪数、gold覆盖率和失败项；七图仍仅为小规模试验 |

### 执行顺序与依赖

- P01、P02 与 P03 的填写可并行开展。
- P04 依赖 P01、P02，以及对应图的必要 P03 信息；P05 依赖该图候选路线获准使用。
- P06 可基于设计输入先产生种子，完整跨图版本再使用 P05 的写回记录。
- P07、P08、P09 使用 P05 及相应对象候选；不完整证据仍保留为未知。
- P10 的协议设计可提前，实际导出依赖相应采集结果。
- P11 是后续分支，不是首批非变更数据发布的前提。
- P12 的族划分审核应提前；最终标签冻结在导出之后。P13 只发布已验收的范围。

建议先用 **D208 外圈（train）** 验证新图完整链路；D207作回归对照。
随后扩展其他外圈。D209/D210按预留集合构建并独立审核，不利用测试正确标签反复调方法。

## 三、自动补足不等于自动获得真值

| 数据来源 | 默认处理 |
|---|---|
| 原图明确字段 | 保存原字段、实体或位置证据；仍允许提取错误被纠正 |
| 确定性规则执行 | 保存规则版本、输入、结果和来源；使用 system 等相应质量 |
| 几何匹配、规则语义抽取或 LLM 推断 | 作为 candidate/弱标候选；说明推断依据与适用范围 |
| 未覆盖、歧义、失败 | 显式 unknown/待审核，不补成“无关联”，不填默认真值 |
| 工程师审核的具体字段 | 记录人员、日期及依据；仅提升实际审核字段，不整条/整图一键 gold |

保留拒绝、冲突和失败项。阶段状态显示 completed，不代表内部每个字段都得到有效规则和正确决议。
对功能目的，只能在图纸、装配信息、规范或工程确认确有支持时标注；不能把制造要求换名后当作已验证功能意图。

## 四、工作簿各页怎么用

| 工作表 | 用途 | 现在是否需要你填写 |
|---|---|---|
| 01_填写说明 | 状态、颜色、填写顺序与边界 | 阅读即可 |
| 02_构建计划 | 任务、责任、依赖、验收及进展 | 可在黄色意见栏补充要求；无需全部填 |
| 03_本轮确认 | 少量真实需要你的信息 | 优先填写对应图的必要确认项 |
| 04_七图台账 | 7份外圈现状、分组和下一步 | 已按v2预填；由我维护，避免重复填写 |
| 05_候选审核 | 每图路线、对象、意图、对应和轨迹的审核入口 | 大部分待自动生成；不要现在填空白语义标签 |
| 06_变更案例 | 真实A/B或变更指令登记 | 后续可选；无案例不影响前面阶段 |

05表的审核ID只是工作项ID，不是训练标签中的对象或事件ID。
已有3D备用路线和D207弱标材料提供了相对链接，其余候选尚未生成，必须等候选内容和证据齐备后再审核。
结论可填“通过 / 修改后通过 / 驳回 / 待补证据 / 不适用”，也可填写更具体的文字。

## 五、填完后如何交回

1. 在黄色单元格填写；空白保持为“未填写”，不自动理解为否定或批准。
2. 审核结论须带实际审核人和依据；日期建议 `YYYY-MM-DD`。
3. 保留原模板，另存为例如 `IntentCAD_数据集构建计划与填写表_已填.xlsx`。
4. 将填好的文件路径交给我或接手agent；随后先检查冲突和缺项，再生成新数据版本。
5. 本工作簿是计划/审核载体，**不是当前训练器可以直接导入的文件**。对象合并、意图和轨迹需要新协议适配；既有事件字段可复用现有 annotation 接口。

请整体保留该目录及其在项目中的相对位置。工作簿中的材料链接指向项目现有文件；单独复制xlsx后，这些相对链接可能失效，但表内图号、任务ID和说明仍可使用。
