## 2. 上游的级联是**显式**的，只是写成了散文

这是本轮最重要的发现。`mogong_patch` 的 `evidence` 字段里，
**级联公式被人工推导后写在文字里**。

取 `D207NQ.01_325_粗磨外沟.json`：

```
De = {nominal: 64.562, source: lookup_allowance_calculate,
      evidence: "0.07 +0 -0.03 (supplement)"}
R  = {nominal: 5.64,   source: product_drawing_calculate_r,
      evidence: "product=5.72-deduct=0.08"}
ae = {nominal: 8.54,   source: product_drawing_calculate_ae,
      evidence: "product=8.5+(C细磨-C终磨)/2=8.5+0.08/2"}
C  = {nominal: 17.08,  source: copy_from_other_process,
      evidence: "细磨平面.C"}
D  = {nominal: 72.06,  source: copy_from_other_process,
      evidence: "粗磨外径.D"}
```

**`ae = 8.5 + (C细磨 - C终磨)/2` 这一行是决定性证据。**

沟位置 `ae` 的取值**依赖于另外两道工序的平面尺寸 C**。
这正是我们用解析法独立推出的那条约束：

$$\text{land} = ae - z - c,\qquad z=\sqrt{R^2-(R-h)^2},\ h=\tfrac{D-De}{2}$$

外径往下磨 → $h$ 变小 → $z$ 变大 → 台肩被吃掉 → 工程师把 `ae` 调大补回来。
上游的 `ae` 公式就是这条闭环的手工版本。

**所以级联不是我们的发明，也不是上游没有——上游有，但它是**
1. **逐例手工推导**的（`evidence` 是散文，不是可执行的关系），
2. **不校验**的（推错了没人会发现），
3. **不可推广**的（换一个图号要重新推）。

而 `source_type` 这一列已经是一套**半结构化**的分类：
`product_drawing_*` / `lookup_*` / `copy_from_other_process` / `fixed*`。

### 这对我们的意义

**我们不缺级联，我们缺的是把散文变成图，然后校验它、并推广它。**

这恰好是一个干净的论文贡献：
- 上游：1410 张卡，每张的级联公式都是人写的散文
- 我们：把 `evidence` 里的公式**自动解析**成依赖图，跨 14 张图纸**挖掘**不变式，
  然后用图做**校验**，并对**新设计**预测合法的级联

而且 `evidence` 是**可解析的**——`"product=8.5+(C细磨-C终磨)/2=8.5+0.08/2"`
就是一条可还原的表达式。这是数据，不是人工标注。

## 3. L3（图纸级）可行性的诚实核查

### 3.1 坐标系是共享的 —— 好消息

对 `D207NQ.01` 的 507 道工序做位置匹配（类型 + 圆心/中点坐标，1 位小数）：

```
可比较的几何键总数:  7095
  跨工序可追踪:      7012  (98.8%)
  只在一道工序里:      69
```

**98.8% 的几何在工序之间位置稳定。** 工序图之间坐标系一致，
所以"同一物理特征在下一道工序还在不在"是**可判定的**。

### 3.2 但工序图画的不是"零件的当前尺寸" —— 坏消息

各工序最大的圆/弧半径：

```
100_总图        最大R 8.467    圆/弧 15
105_细车Ⅰ       最大R 10.205   圆/弧 33
115_车外沟      最大R 8.467    圆/弧 15
315_粗磨外径     最大R 5.505    圆/弧 21
325_粗磨外沟     最大R 5.505    圆/弧 24
360_终磨外径     最大R 8.467    圆/弧 15
330_清洗(火前)   无圆/弧
```

**没有 R=36（外径 72）或 R=30（内径 60）的圆。**
工序图画的是**剖视示意图 + 局部放大 + 标注**，不是按比例的零件图。

逐实体对比相邻两道工序（`320_粗磨外圈内径` → `325_粗磨外沟`）：

```
共有 236 个实体，其中几何改变 15 个：
  MTEXT  5   ← 标题栏、参数名(d→di, Vdsp→Vdip, Ki→R)、标准件名
  ARC    5
  LINE   5
其余 189 个新增 / 189 个删除，是模板重新实例化导致 handle 换号
```

那 5 个 ARC + 5 个 LINE 变的是**砂轮/标准件的局部剖面**
（半径 1.5 / 2.0 / 2.5 / 0.75 / 5.505 这个量级），不是零件轮廓。

### 3.3 结论

**"每步工序图的几何修改"在图纸 entity 层是观测不到的。**
零件的尺寸变化**只存在于参数值和标注文字里**。

所以 L3 若定义为"追踪图纸 entity 的变化"，它会得到几乎全是标注文字 diff 的结果，
**无法支撑"零件几何是否合法"的判定**。

**L3 若定义为"参数化零件模型 → 约束传播 → 重新合成图纸"，
它其实是可做的——但此时图纸是 OUTPUT 而不是 STATE。**

上游的 `mogong/README.md` 那 16 条边界恰好证明了这一点：
它们全部是"从模板改出来的图纸如何保持和模板一致"的问题，
**上游自己就没有零件几何模型**，它只有模板 + 改字 + 改箭头。

## 4. 三层的最终判断

| 层 | 内容 | 判定 |
|---|---|---|
| **L1 零件级** | 特征标量值 + 拓扑关系 + 约束 | **可做，且是全部工作的地基** |
| **L2 图元级** | 每特征一个参数化图元（圆柱/圆环/锥/平面），解析判干涉与公差区间 | **可做**，L1 的自然扩展 |
| **L3 图纸级** | 追踪/校验图纸 entity | **不是状态，是产物**；作为"生成"可做，作为"判定"不可做 |

**关键换位：**

我们不是"从图纸出发追踪修改"，而是

```
设计图 → 参数化零件模型 → 工艺链（每步是模型上的变换）→ 状态序列 → 合法性判定
                                                              ↓
                                                        工序图（合成产物）
```

图纸在**末端**。这与标题 "Cascaded Modification" 是一致的：
被级联修改的是**零件模型**，工序图是级联的结果。
