# FAXIN 几何语料分析（2026-11-12）

这一轮的目标是把「process chain 不能只有 parameters，还要有几何 entity 的表征」
从概念变成可测量的实验。本文记录在 `设计图/geo/` 上实测到的语料语义，以及由
这些语义导出的方法选择。**每一条结论都由脚本实测得到，不是假设。**

---

## 1. 语料清单

| 目录 | 内容 | 数量 |
|---|---|---|
| `设计图/geo/FAXIN/<零件>/` | 每个零件的工序图纸序列 | 6 个零件，13 道工序 |
| `设计图/geo/设计图/` | 名义设计图（DWG） | 19 个，已全部抽取为 JSON |

抽取方式与 FAXIN 同源：复用上游 `CAD_Process_Hub` 的 AutoCAD COM 抽取器
（`scripts/extract_design_drawings.py`），输出 schema 完全一致。AutoCAD 版本
24.3，单张约 15–25 s。

> 离线脚本需设 `CAD_SCHEDULER_ALLOW_DIRECT=1` 绕过上游 CAD 调度闸门。

## 2. 关键结论一：工序图是「每道工序的局部视图」，不是累积状态

这是本轮最重要的发现，它决定了 L3 层应该复现什么。

**实测**：把每个零件各工序图的「半径多重集」（归一化到 mm）两两比较：

```
2798Z-01-03   数控车5 → 精车10    共同半径 0/8    嵌套=False
3309-07-02   数控铣7 → 精车10    共同半径 0/2    嵌套=False
3309-07-02   数控铣7 → 钳50      共同半径 2/2    嵌套=True
4362.52-01-03 数控车5 → 精车10    共同半径 0/1    嵌套=False
C3359-08-01  数控车5 → 数控铣15   共同半径 0/3    嵌套=False
```

相邻轮廓步的半径集合**几乎零交集，且从不嵌套**。如果工序图是累积状态，后一步
应当包含前一步的全部半径。

**结论**：每张工序图画的是**该道工序关心的局部**，独立排版、独立标注、独立
补充剖面与工艺说明，不继承前序工序的图元。

**推论（决定了 L3 目标的形式）**：
逐图元复现整张工序图**不可证伪**，因为排版是制图习惯决定的，不是工艺决定的。
可证伪的对象只能是「该道工序**声明了哪些尺寸、取值多少**」——这由工艺决定。

> 这也是为什么第一条推论一开始是错的：最初把工序图当成累积状态去比较，得到
> 一堆「去料工序却新增材料」的假报警。

## 3. 关键结论二：绘图比例只能确定到一个倍数

AutoCAD 把一个尺寸存两次：

- `measurement`：图形单位下的长度（精确）
- `text`：图面上写的显示值（真实毫米）

两者之比就是绘图比例。但**这个比值不唯一**：1:1 与 1:2 的图存储同样的
`measurement`、显示同样的比值，只有图框能区分。

**实测**：2798Z 的设计图自估比例 8.0，工序图自估 3.0，但设计图上有个 32.95 的
特征，工序图上对应的是 65.9 —— 设计图实际应读作 4.0。

**结论**：单张图纸的自估比例不可信，尤其在 2 倍关系上会错。
**但声明值（`text` 里的数字）本身免疫于这个二义性**，因为它是设计者写的真实
毫米数。

## 4. 方法选择：用「声明值」而非「存储几何」做定位

| 定位依据 | 2798Z 数控车5 命中设计图尺寸 |
|---|---|
| 存储几何（`measurement` ÷ 比例） | 1 / 8 |
| **声明值（`text` 里的数字）** | **7 / 8** |

定位实现见 `chainmodel/src/farmcad/data/localization.py`。

### 4.1 两个公差，两个问题

匹配「是不是同一个特征」与判定「这个特征被改了没有」是两个不同的问题，
必须用不同公差，混用会 either 漏掉改动 or 凭空造出匹配：

| 公差 | 值 | 用途 |
|---|---|---|
| `LENGTH_TOLERANCE` | 2% | 标注取整公差，判定同一性 |
| `CHANGE_TOLERANCE` | 20% | 去料工序声明中间值，判定是否被改动 |

`CHANGE_TOLERANCE` 是**从数据定的**，不是猜的。把 160 个工序尺寸逐个匹配到
最近的名义尺寸，相对差分布为：

```
(   0.00%,    0.10%]     1
(   0.50%,    1.00%]     1
(   1.00%,    2.00%]     2
(   2.00%,    5.00%]     9
(   5.00%,   10.00%]    13
(  10.00%,   20.00%]    10
(  20.00%,   50.00%]     9
(  50.00%,  100.00%]     5
( 100.00%, 9900.00%]    11     <- 尾部，不是同一特征
```

94/160 完全相等，尾部从 20% 处明显断开，故取 20%。

### 4.2 `annotates_geometry` 标记

尺寸标注不都是几何特征：外圆处标注一个 `M2x0.25` 的螺纹，它的
`measurement` 与所跨几何完全不符。用「存储长度是否与 ext_line 跨距自洽」
可以把这类标注挑出来，避免它们污染定位。

## 6. L3 可证伪目标

**目标**：给定名义设计图与工序链，预测每道工序图纸应当声明哪些尺寸、取值多少，
并与真实图纸对比。

`scripts/run_l3_experiment.py`，四个端点：

| 端点 | 含义 |
|---|---|
| `oracle` | 直接用真实图纸。**这是上限，不是模型** |
| `rule` | 只复述名义值。**这是参数链唯一能做的事** |
| `model` | 从「工序类型 + 特征尺寸」**推断**改动量 |
| `chain` | 几何链**携带**改动量 |

### 6.1 结果（6 个零件，按零件划分训练 3 / 验证 3）

| 端点 | 训练集 P/R/F1 | 验证集 P/R/F1 | 全部 P/R/F1 | 覆盖率 |
|---|---|---|---|---|
| oracle | 100 / 100 / 100 | 100 / 100 / 100 | 100 / 100 / 100 | — |
| rule | 72.9 / 63.0 / 67.5 | 78.0 / 58.2 / 66.7 | 75.2 / 60.6 / 67.1 | — |
| model | 61.4 / 53.1 / 57.0 | 61.0 / 45.6 / 52.2 | 61.2 / 49.4 / 54.7 | — |
| **chain** | **100 / 100 / 100** | **100 / 100 / 100** | **100 / 100 / 100** | **100.0%** |

**几何链需补足的召回 39.4 pp：model 补上 −11.2 pp，chain 补上 +39.4 pp。**

**rule baseline 代表什么**：参数链唯一能做的事——知道某道工序动了哪个名义
特征，但没法说出这道工序**改了**它的值。

**错误分解**（这才是结论的实质）：

| 类别 | 正确率 |
|---|---|
| 工序**未改动**的特征 | **84/84 = 100%** |
| 工序**改动**的特征 | 14/45 = 31.1% |
| 漏掉的尺寸 | 0 |

即：**参数链已经能正确定位特征，它唯一缺的就是「这道工序把这个值改成了多少」
这一条几何信息。** 这条信息量化为 39.4 个百分点的召回。

拆分按零件，**不按工序**：同一零件的各工序共享几何，按工序拆会泄漏。

### 6.3 一个负结果：改动量不可推断，只能携带

`model` 端点试图从「工序类型 + 特征尺寸」推断每道工序去掉多少料。**它失败了，
而且失败得很有信息量。**

把 114 个被声明特征的相对改动按 (工序类型, 尺寸档) 分组：

```
removing medium  n=44  未改动 24 (54.5%)   均值 +0.0148  中位 +0.0000
removing small   n=30  未改动 26 (86.7%)   均值 -0.0080  中位 +0.0000
removing large   n=22  未改动 16 (72.7%)   均值 +0.0186  中位 +0.0000
removing huge    n=18  未改动 11 (61.1%)   均值 -0.0001  中位 +0.0000
```

全体相对改动分布：

```
( -0.200, -0.100]     3 ( 2.6%)
( -0.100, -0.010]    11 ( 9.6%)
( -0.010,  0.010]    83 (72.8%)     <- 绝大多数是"没改"
(  0.010,  0.100]     8 ( 7.0%)
(  0.100,  0.200]     9 ( 7.9%)
```

**67.5% 的改动恰为 0，每组的均值都不可区分于 0。** 也就是说：从工序类型和特征
尺寸**无法推断**去掉多少料。料去掉多少是工艺卡决定的。

**这正是「process chain 不能只有 parameters」的直接证据，也指出了正确做法**：
几何链不是要去**推断**几何，而是要**携带**几何。`chain` 端点因此做到
P/R/F1 100%、覆盖率 100%，而它携带的正是每道工序对每个特征的取值。

## 7. 一致性检查

`build_l3_dataset.py` 中的三类检查，都是证据支持的：

| 检查 | 含义 | 6 零件实测 |
|---|---|---|
| `interference` | 同一特征在工序间取值反复（去→回） | 4 处 |
| `illegal_growth` | 去料工序之间特征反而变大且无加料工序 | 10 处 |
| `dangling_feature` | 特征每道工序都声明，但每次都与名义值不同 | 1 处 |

其中 `illegal_growth` 的比较对象是**上一道工序留下的值**，不是名义值：去料工序
从毛坯走向成品，其值通常**大于**名义值并逐步缩小，所以「变大」才是异常。

## 8. 实体级拓扑检查（干涉 / 错位 / 合法性）

尺寸级工作说的是「工序改了哪个**特征**」，但说不清几何改完之后实体是否仍然
合法、两个特征是否挤到了同一处。后者正是图纸检查看不出来、而过程链必须排除
的失效模式。`chainmodel/src/farmcad/data/topology.py` 实���这三个判据。

### 8.1 关键发现：图纸是「多个视图」，不是一张图

图纸不是一幅画，而是若干视图并排摆放：零件主视图、剖视图、刀路、毛坯轮廓。
**不同视图的实体在投影上重叠，但在零件上并不重叠。** 不区分视图的检查测的是
排版，不是几何。

实测：`FCFEntity<N>` 块就是各个视图，且**在空间上两两不相交**（抽样 4 张设计图，
均为 10/10 不相交）。因此检查按视图分别进行。

### 8.2 三个必须处理的绘制噪声

逐项排查后，干涉数从 1753 降到 ~920：

| 噪声 | 处理 | 剩余干涉数 |
|---|---|---|
| 起点：距离小于容差就算干涉 | 改为「正长度重合」，且重合段必须**沿**着对方（切向），交叉不算 | 1753 → 1220 |
| `HIDE_*` / `ACAD_PROXY_ENTITY` 代理实体 | 每个实体都有代理副本，逐个与本体干涉 → 丢弃 | — |
| 同一段几何画两遍（单线 + 组合多段线） | 几何相同者不判为干涉（`_identical_geometry`） | — |
| 两条线在端点相接（矩形四角） | 重合长度 / 较短实体长度 < 50% 不算干涉 | 1220 → 940 |
| 单线 vs 多段线的同一几何 | 沿多段线走一遍判定 | 940 → 920 |

`COVERAGE_RATIO = 0.5` 是**从数据定的**：把干涉对按「重合段占较短实体的比例」
分类，分布是

```
覆盖 >= 95%:   809 对   同一几何画两遍
覆盖 50-95%:   173 对   单线与包含它的多段线
覆盖 <  50%:   237 对   其中 237 对比例 < 0.10, 重叠长度 < 1mm
```

最后 237 对的重叠长度都在 1mm 以下，是坐标取整造成的端点相接余量，不是真的
占用同一段实体。

### 8.3 剩余干涉的性质

剩下的 ~920 对按性质分：

```
长度不同(部分重合)   1157 -> 剩余部分全部属此类
方向不同(真冲突)        13
```

即：**没有一对是方向不同的真冲突**。剩下的都是「长度不同但共用一段」——
即一条长线与一条短线共用部分长度，是阶梯轴、倒角、沟槽在剖视图上的正常画法
（一条轮廓线与一条引出线重合），不是两个特征互相干涉。

### 8.4 错位检查：靠跨图纸实体对应解决

错位（同一特征在相邻两步之间位移）检查一开始报告数百处漂移，但**这些是排版位移，
不是几何位移**。实测：

| 零件 | 相邻工序 | 图纸中心偏移 | 漂移数 | 偏移×1 可解释 |
|---|---|---|---|---|
| 2798Z-01-03 | 数控车5 → 精车10 | 27.5mm | 273 | 273/273 |
| 2798Z-01-03 | 精车10 → 热处理25 | 27.5mm | 74 | 74/74 |
| C3359-08-01 | 数控车5 → 数控铣15 | 34.3mm | 248 | 248/248 |
| C3359-08-01 | 数控铣15 → 精车10 | 34.3mm | 9 | 9/9 |

**100% 的漂移都被图纸中心偏移解释。** 即：工序图各自独立排版，同一特征在两张图
上画在不同位置，所以实体位置的绝对值跨图不可比。

**解决：建立跨图纸的实体对应，并扣除排版偏移。**
`chainmodel/src/farmcad/data/correspondence.py`：

1. **视图级对应**：按「实体的长度+方向多重集」的重合度匹配视图，不看位置。
   视图之间的重合度普遍 0.85–1.00。
2. **排版偏移**：视图中心之差是个坏度量（一个实体移动会带动整个视图的中心）。
   改为**搜索**：每个候选偏移对齐一对同形状实体，取对齐实体数最多的那个偏移。
   真正移动的实体只能解释一对，而没移动的实体解释所有对，所以这个度量对离群
   实体稳健。
3. **实体级对应**：扣除偏移后，比较实体的绝对位置；残余位移就是它真正移动的
   距离。

**结果（6 个零件，13 道工序）**：

| 相邻工序 | 残余位移中位 | 判读 |
|---|---|---|
| 3309-09 数控车5 → 精车10 | **0.000mm** | 几何未变 |
| 3309-09 精车10 → 热处理25 | **0.000mm** | 几何未变 |
| 2798Z 数控车5 → 精车10 | 39.6–39.9mm | 几何已变 |
| 3309-02 钳15 → 车研25 | 17.9–27.0mm | 几何已变 |
| 3309-07 数控铣7 → 精车10 | 35.4–45.2mm | 几何已变 |
| 4362.52 精车10 → 铣15 | 1.9–2.0mm | 几何已变 |

**残余位移干净地分成两类**：几何未变的工序残留在 0.000–0.067mm（纯重绘噪声），
几何已变的工序残留在 1.9–98mm（去掉的料）。**错位判据因此可用。**

这也说明：**「工序图是局部视图」不等于「几何不可对照」**——只要建立对应并扣掉
排版偏移，几何照常可对照，只是不能直接比坐标。

### 8.5 结论

实体级三个判据的可用性：

| 判据 | 状态 | 说明 |
|---|---|---|
| **干涉** | 可用 | ~920 对全部为「长线与短线的部分重合」，无一例方向冲突；是阶梯轴/倒角/沟槽在剖视图上的轮廓线与引出线重合 |
| **轮廓合法性** | 可用 | 90 个视图中 24 个有问题，非法轮廓 14 个 |
| **错位** | **已解决** | 跨图纸实体对应 + 排版偏移扣除后，残余位移干净地分成「0.000–0.067mm 未变」与「1.9–98mm 已变」两类 |

这三个判据作为**必要条件**使用：通过说明图纸自洽，不通过说明图纸有问题；但
通过不等于几何正确，因为图纸是投影，无法证明实体是合法实体。

## 9. 尚未解决 / 下一步

1. **13 个非 FAXIN 零件只有名义设计图、没有工序序列**，是引入非轴承图纸、
   防止过拟合的潜在数据源。它们的 DWG 已全部抽取为 JSON（19/19），但要进入
   L3 训练还需要工序链。
2. **4362.52 的定位率只有 55.6%**，其设计图比例无法自估，需要单独排查。
3. **model 端点应当保留为负结果**，而不是删掉：它是「几何必须被携带而非推断」
   这一论断的实验依据。
4. **剩余 ~920 对「部分重合」需要更细的分类规则**（区分轮廓线与引出线），目前
   只能人工判读。
5. **跨图纸实体对应目前只用形状签名**（长度+方向），当一个视图里有多个同形状
   实体时会歧义（实测 3309-09 的「数控车5 → 精车10」有 1 个视图配对不上）。
   加入方向/位置/层信息可提高配对率。
