# FAXIN 语料：几何状态的真正来源

日期：2026-11-12
接续 `geometry-grounding-gap-20261112.md`、`l3-feasibility-20261112.md`

## 1. 这批数据是什么

`设计图/geo/` 下有两组：

| 目录 | 内容 | 数量 |
|---|---|---|
| `设计图/` | 设计图纸 DWG（NX 2D Exchange 导出，附 .log 记录导出过程） | **19** 个 DWG |
| `FAXIN/` | **每个零件一个文件夹，文件夹内每个 JSON 是一道工序的图纸** | 6 零件 / **75 道工序步** |

`FAXIN` 的文件名带工序号和工序名：

```
C3359-08-01/
    C3359-08-01-下料0.json
    C3359-08-01-数控车5.json
    C3359-08-01-精车10.json
    C3359-08-01-数控铣15.json
    C3359-08-01-钳20.json
    C3359-08-01-热处理25.json
    C3359-08-01-车研30.json
    C3359-08-01-外磨35.json
    ...
```

**这就是我们要的结构：同一零件在每道工序之后的一张图纸。**
上游 `temp/modifier` 的工序卡做不到这一点（那是同一模板实例化出的标注图，
零件尺寸不变）；这里是真的在画零件。

## 2. 三个关键验证

脚本：`scripts/audit_faxin_corpus.py`

### 2.1 零件轮廓在加工步之间真的在变

各零件的最大圆/弧半径（只列画出零件轮廓的步）：

```
2798Z-01-03     数控车5:48.344   精车10:29.379
3309-02-02      精车10:32.445
3309-07-02      数控铣7:15.0    精车10:23.177   钳50:15.0
3309-09-01      精车10:19.18
4362.52-01-03   数控车5:21.189   精车10:19.144   铣15:8.25  钳20:8.25
C3359-08-01     数控车5:72.548   精车10:32.807   数控铣15:26.289
```

**C3359-08-01：72.548 → 32.807 → 26.289。**
粗车留大余量，精车去掉，铣削再去一刀。这是物理上正确的加工序列。

### 2.2 尺寸标注携带真实几何

`DIMENSION` 实体有两个字段：
- `measurement` = AutoCAD 存储的被测长度（图纸单位）
- `ext_line1_point` / `ext_line2_point` = 尺寸界线所在的几何点

**如果 `measurement` 等于两点的几何跨度，那么这个标注就绑定到了它所测量的几何。**

实测：**192 个尺寸标注中 149 个（77.6%）`measurement` 与几何跨度一致。**
不一致的多数是角度标注（跨距不是它的语义长度）和带特殊格式的标注。

而且 `measurement` 与显示文字的比值是**恒定的绘图比例 3.0**（六个零件全部是 3.0）：

```
外磨35:  measurement=24.2316  跨距=24.2   显示=[8.2, 0.05]  比例=2.955
         measurement=290.9316 跨距=290.9  显示=[96.977,0.051] 比例=3.0
         measurement=180.4416 跨距=180.4  显示=[60.147,0.051] 比例=3.0
```

**所以：真值(mm) = measurement / 3.0。** 这意味着每个标注都有
**毫米级、带真实几何依据的真值**，而且这个真值可以从几何自动读出，不需要人工标注。

### 2.3 级联在图纸上是可观测的

关键方法：**按"标注测的是什么几何"配对跨步标注**，而不是按位置。
因为每道工序图是独立排版的，位置会变，但**跨距 + 方向角**是稳定的。

结果（18 个可跨步配对的标注）：

```
3309-02-02  跨距18.0   下料0:10 -> 数控车5:6.5 -> 热处理20:6.5 -> 外磨30:6.25 -> 热处理35:6.25 -> 表面处理55:6.25
3309-07-02  跨距24.0   下料0:12 -> 数控车5:8.5 -> 热处理20:8.5 -> 外磨30:8.25 -> 热处理40:8.25 -> 表面处理65:8.25
C3359-08-01 跨距24.2   数控车5:8.5 -> 精车10:8.5 -> 外磨35:8.2
C3359-08-01 跨距19.0   精车10:6.4 -> 钳50:6.35
```

**4 个标注的值沿工艺路线单调递减，其余恒定或非单调。**
这就是级联的直接观测：车完留余量 → 磨到接近终值 → 稳定。

## 3. 三个必须处理的数据问题

### 3.1 非加工步要合并

热处理、清洗、表面处理、磁粉检测这些步**不改变几何**，只是工艺标记。
2798Z-01-03 的 `清洗55` 和 `表面处理65` 的几何指纹与上一步**完全相同**。

**做状态机时必须合并**，否则状态序列会被无意义的步打断，
而且"这一步改了什么"会全是空操作。

### 3.2 不是每步都画零件

75 步里只有 **12 步**画出了零件轮廓（半径 ≥ 8）。
其余的步（钳工、热处理、清洗、外磨）画的是**局部剖面 + 砂轮/标准件**。

所以图纸级的状态不是"每步都有完整零件"，而是**稀疏采样**：
只有车、铣这些去料工序才重画零件。

**这实际上是好消息**：它说明"哪一步真正改变几何"是**可从图纸判定的**
（轮廓半径变了 / 出现了新轮廓），这本身就是一个可以学的信号。

### 3.3 尺寸标注的配对要靠几何，不能靠位置

同一道工序的图纸和上一步的图纸，尺寸标注的**位置会变**（重新排版），
但**被测几何的跨距和方向不变**。用几何配对才能跨步追踪。

注意 3309-09-01 有一条：
```
跨距24.0  数控车5:8.5 -> 热处理12:8.25 -> 热处理20:8.25 -> 外磨30:8.2 -> 热处理35:8.25 -> 表面处理60:8.25
```
**非单调**（8.25 → 8.2 → 8.25）。这是**公差带内的标注取整**，
不是真实的几何回退。判定时必须用公差区间而不是点值。

## 4. 这批数据补上了什么

对照上一轮的数据可得性表：

| 需要的东西 | 之前 | 现在 |
|---|---|---|
| 逐步几何状态 | 无 | **75 步**（6 零件） |
| 真实尺寸真值（mm） | 无 | **192 个标注**，比例 3.0 恒定 |
| 跨步级联观测 | 无 | **18 条可配对轨迹**，4 条单调递减 |
| 加工步 / 非加工步区分 | 无 | 可判定 |
| 几何 vs 标注的区分 | 无 | 可判定（轮廓半径变化） |

**这是目前唯一能支撑"图纸级几何状态机"的数据。**

## 5. 缺什么

### 5.1 只有 6 个零件，且只有 1 个套圈类

FAXIN 的 6 个零件（2798Z / 3309-02 / 3309-07 / 3309-09 / 4362.52 / C3359）
和 D207NQ.01、保持架、内外圈**不是同一类零件**——它们是另一类（从工序名看：
下料/数控车/精车/数控铣/车研/外磨/珩研，是钢件而非轴承套圈）。

所以这批数据**不能直接接进现有数据集**，需要作为**独立的几何语料**，
用它的**方法**（几何配对 + 轮廓追踪 + 尺寸真值提取）去补现有数据集。

### 5.2 `设计图/` 里还有 13 个 DWG 没有抽取

```
1340.1-02-01   1341.1-05-01   1343.1-11-01   1354-04-01
1355-08-01     1356-05-01     1708C-01-02    1708D-01-02
1708E-01-02    2720A-02-04    2723A-01-03    2730-01-03
3309-04-02
```

抽取器在 `NOVbcj/smartCAD/CAD_Process_Hub/src/TQ/table_process/table_extraction/_server.py`
的 `process_dwg_to_json(dwg_path)`，走 AutoCAD COM。
环境里 `ezdxf 1.1.4` 可用但**读不了 DWG**（需要 ODA 转换器或 AutoCAD）。

**注意**：这 13 个 DWG 是**设计图**（每零件一张），不是工序图。
它们对应的是 `设计图 → 初始状态`，而 FAXIN 的工序图是 `状态序列`。
两者配对才是完整的"设计图 + 级联修改"。

### 5.3 没有加工参数

用户说得对："这些图纸没有详细的加工参数，但是有比较清晰的几何建模。"

所以这批数据提供的是**几何侧真值**，不提供参数侧。
参数侧我们已经有 25 个案例（`chainmodel/data/processed/combined-batch-v1`）。

**两批数据是互补的，不是替代关系。**

## 6. 由此确定的技术路线

FAXIN 语料给我们的不只是数据，更是**三个可复用的方法**：

### 6.1 几何配对（代替 handle 配对）

```
跨步追踪一个特征 = (被测跨距, 方向角) 而非 (handle, 位置)
```

这个方法同时解决了上游工序卡"handle 每次都变"的问题。
**这是"拓扑感知几何定位"的一个具体、可执行、可验证的算法。**

### 6.2 尺寸真值提取

```
真值(mm) = dimension.measurement / 绘图比例
```

比例从同一零件内多个标注的 `measurement / 显示值` 的众数自动求出
（实测六个零件全部是 3.0，且众数占比很高）。
**这自动生成了 ground truth，不需要人工标注。**

### 6.3 轮廓追踪 + 加工步判定

```
这一步是否改变几何 = 轮廓半径是否变化 / 是否新出现
```

**这是"几何操作分类"的天然弱标签**：不需要人工标注工序属于哪种几何操作，
从"轮廓变没变、变成多少"就能推。

## 7. 建议

按上一轮定的"先讨论清楚问题模型和算法"，这一轮把 L3 从"存疑"变成
**"有数据支撑，但语料是另一类零件、规模小、需要方法迁移"**。

具体建议：

1. **把上面三个方法实现成 `chainmodel` 里的独立模块**
   （几何配对 / 尺寸真值提取 / 轮廓追踪），
   先在 FAXIN 语料上验证（这是算法的验证集，不是训练集）。
2. **在现有 25 个案例上验证同样的方法**（那批数据有 `feature_members` 的位置，
   正是"定位"任务的监督信号）。
3. **13 个 DWG 的抽取**：看 AutoCAD COM 在当前机器上是否可用。
   如果可用，就多 13 个零件的设计图，能配成"设计图 + 工序序列"。
4. **L3 的合成**：FAXIN 已经给了"每步图纸长什么样"的真实样本，
   可以用它来**训练/验证**我们的合成器，而不是靠承诺。
