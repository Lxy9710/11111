# 划分闭合性与路线证据核查（2026-11-11 修正）

日期：2026-11-11。本文件记录一次划分缺陷的发现与修正，以及在核查过程中
暴露的**路线证据强度问题**。这些问题会直接影响论文 §3.8 的可写内容。

---

## 1. 缺陷：验证/测试集不是训练词表的闭集

**现象**。`Vocabulary.build` 只用 **train** 划分构建工序与参数词表
（`data/dataset.py`）：

```python
training = [c for c in cases if c.split == "train"]
ops = sorted({e["operation"] for c in training for e in c.target["events"] if e["action"] == "OP"})
```

但第一版划分把 `cage-series-1`（`6006FBC1/P4YA6.66`）放进了 validation。
该族是**唯一**能提供 `调质` 工序与 9 个参数的族，于是：

```
validation: 3 cases
  NOT CLOSED, unseen operations  : ['调质']
  NOT CLOSED, unseen parameters : ['S-S1', 'S1-S2', 'Vbc', 'Ve', '倒铆钉孔角',
                                   '内外倒角', '圆周等分', '孔数+Mc', '销子数量']
```

**后果有两层**，都严重：

1. **模型无法输出** `调质`。该工序在验证集里的预测必然错，
   但这与模型能力无关，是词表里根本没有这个 token。
2. **模型选择信号被污染**。`best_validation_loss` 用来挑 best checkpoint。
   验证 loss 里含着一个**永远无法降低**的常数项，
   于是 best checkpoint 的选择实际上被"这个 epoch 能不能猜对那 9 个参数"主导，
   而不是被整体拟合质量主导。

第一版划分还把 `cage-series-206` 放进 test，同样带 9 个未见参数。

**注意**：这一缺陷在 `validate-data` 里是**可见**的
（`vocabulary_coverage.validation.unknown_parameters = 9`），
但我第一版划分时只看了 `status: valid`，没有逐 split 读覆盖数字。

---

## 2. 修正

新增两个脚本，把"闭集"变成**发布前的前置检查**而不是事后观察：

| 脚本 | 作用 |
|---|---|
| `scripts/analyze_split_closure.py` | 逐族分析哪些工序/参数只有单一族能提供，并给出每个族的可留出性 |
| `scripts/check_split_closure.py` | 校验当前划分对 train 词表闭合，**不闭合则退出码 1** |

分析结论：

| 族 | 可否留出 | 原因 |
|---|---|---|
| `outer_ring-series-207` | **否** | 独占 29 个工序、19 个参数（全部磨工类） |
| `cage-series-1` | **否** | 独占 `调质` 与 9 个参数 |
| 其余 17 个保持架族 | 是 | 词表完全由其他族覆盖 |

最终划分（train 20 / validation 3 / test 2，全部闭合）：

| split | 案例 | 族 | 口袋形状 |
|---|---|---|---|
| train | 20 | 15 族 | 11 圆 / 8 椭圆 / 1 外圈 |
| validation | 3 | `cage-series-108`, `cage-series-1000905`, `cage-series-304` | 1 圆 / 2 椭圆 |
| test | 2 | `cage-series-1000909`, `cage-series-840207` | 1 圆 / 1 椭圆 |

三个 split 现在都**同时满足**：族不跨、设计指纹不跨、词表闭合。
`validate-data` 三个 split 的 `unknown_operations` 与 `unknown_parameters` 全部为 0。

## 3. 更严重的发现：类别路线的证据强度不足

核查闭集时顺带比对了模板路线与真实路线，发现**三个问题**，
每一个都会限制论文 §3.8.1 能写什么。

### 3.1 模板路线与唯一可核对的真实路线不一致

`6006FBC1/P4YA6.66` 是全批次**唯一**有 `excel_exact` 真实路线的保持架
（`BJ/excel/工序选择.xlsx`，24 道），且 `card_exact` 独立恢复出**完全相同**的 24 道。
两条独立证据互相印证，因此它是**唯一**可用于校验类别模板的样本。

逐道比对：

| | 真实路线（excel + card 双重印证） | 类别模板（`D106NW1(H).56` 导出） |
|---|---|---|
| 工序数 | 24 | 28 |
| 备料段 | **无**（`原材料检验`/`下料`/`锻造`/`锻造检验`） | **有**（4 道） |
| 热处理 | `调质` | `热处理` |
| 机加段 | 23 道 | 23 道 |
| 其它段 | 一致 | 一致 |

**机加段 23 道完全一致**，差异全部集中在**前段的备料与热处理命名**。

这意味着我之前在 Method 框架里写的

> "Comparing the platform's own route table for `D106NW1(H).56` with our
> category-level template shows agreement operation by operation—identical
> process numbers, names, and types across all 28 steps"

**是错的**。我实际比对的样本是 `D106NW1(H).56` 自己的模板导出，
而不是 `6006FBC1` 的真实路线。现在必须改成：

> The machining section agrees operation by operation across all 23 steps.
> The template additionally inserts a four-step preparation section
> (raw-material inspection, cutting, forging, forging inspection) and names the
> heat-treatment step generically as "热处理", whereas the shop-floor route for
> the only cross-checkable cage records "调质" and omits the preparation section
> entirely. We therefore treat the category route as a **machining-ladder
> template with an optional preparation prefix**, not as a verbatim route.

### 3.2 "锻件投料"与技术要求决定是否需要备料段

逐案核查技术要求与路线：

| `锻件投料` | 备料段在路线中 | 案例数 |
|---|---|---:|
| 有 | 有 | 19 |
| 有 | **无** | 2（`6006FBC1`、`C206NW1U(H).56`，两者都来自真实路线） |
| 无 | 有 | 3 |

**图纸写明"锻件投料"（锻件已由外部投料）时，路线本就不该有下料/锻造。**
但模板对 24 个保持架**无条件**插入 4 道备料工序，
其中 19 个案例的图纸明确说锻件是投料来的。

这是一个**设计要求与路线之间的真实不一致**，
而且是可以从图纸证据自动判定的。这恰好是论文主题本身
（设计意图 ↔ 工艺实现的对应），**建议在论文里作为一个正面案例**，
而不是悄悄把模板改对。

### 3.3 `card_exact` 路线存在**截断**

`card_exact` 从上游工艺卡恢复路线。逐案比对尾部：

| 图号 | card 道数 | 尾部停在 |
|---|---:|---|
| `C180506K1NW1R3U(H).56` | 10 | 终检 → 包装（中间缺 14 道） |
| `C205NW1U(H).56` | 8 | 打标记 → 包装（缺 15 道） |
| `C206NW1U(H).56` | 18 | 光饰（缺 5 道：`清洗`/`荧光磁粉探伤`/`清洗`/`终检`/`镀银`/`包装`） |

**`card_exact` 恢复的是**"该次任务实际执行到的工序集合"**，
**不是完整路线**。这一点之前没有写清楚。

影响：

- `card_exact` 的 3 个案例（`C180506`、`C205NW1U`、`C206NW1U`）**路线不完整**，
  其 `target` 的工序序列是残缺的。
- 分类为 `card_exact` 意味着"证据强度高于模板"，但实际上**它比模板弱**
  （模板是完整 28 道）。
- 这 3 个案例中，`C205NW1U(H).56` 与 `C206NW1U(H).56` 是 `template_category` 与
  `card_exact` **同时存在**的，图号相同、路线不同。

**修正后的证据档位强度排序**（原排序有误）：

```
excel_exact  >  template_category  >  card_exact
```

`card_exact` 应当降级为"**部分执行记录**"，
或直接对不完整的 card 路线回退到模板。
否则论文里"逐案记录用了哪一档，让审阅者区分精确路线与推断路线"这句话就站不住。

## 4. 路线模板 JSON 本身已声明的已知限制

`route_templates_v1.json` 的 `known_limitations` 早已写明：

> "保持架仅 1 个图号、滚动体仅 2 个图号，其固定路线证据强度不足。"

也就是说**模板构建时就知道证据不足**，
是本轮的扩充（24 个保持架）让这个问题从"1 个样本"变成"**24 个样本共享一个未经验证的模板**"，
风险被放大了 24 倍。模板里的 `caveat` 也写了"仅 1 个图号样本，证据强度不足，不做阶梯展开"。

## 6. 上游路线表的版本分歧（20260917 vs 20260918）——模板证据链的断点

### 6.1 三份 BJ 路线表的内容

| 表 | 行数 | 图号 | 道数 |
|---|---:|---|---:|
| `20260917/.../BJ/excel/工序选择.xlsx` | 24 | `D106NW1(H).56` | 24 |
| `20260918/.../BJ/excel/工序选择.xlsx` | 54 | `D106NW1(H).56` | 28 |
| | | `6006FBC1/P4YA6.66` | 24 |
| `NOVbcj/.../BJ/excel/工序选择.xlsx` | 28 | `D106NW1(H).56` | 28 |

**同一个图号 `D106NW1(H).56` 在不同部署里有两套不同的路线**：

| | 20260917 | 20260918 / NOVbcj |
|---|---|---|
| 道数 | 24 | 28 |
| 备料段 | 无 | 有（`原材料检验`/`下料`/`锻造`/`锻造检验`） |
| 热处理 | **`调质`** | **`热处理`** |
| 机加段 | 23 道 | 23 道 |
| 其它段 | 一致 | 一致 |

差异恰好是：**20260918 版本加了 4 道备料，并把 `调质` 改名为 `热处理`**。

### 6.2 更关键的发现：`6006FBC1` 与 `20260917 D106` 的路线**完全相同**

23 道机加 + 其它段逐道一致，差异为 0：
`only in 6006: []`，`only in D10617: []`。

也就是说 **20260917 版本的 `D106NW1(H).56` 路线，和 `6006FBC1` 的路线一字不差**。
这说明 `20260917` 那份表里的 `D106NW1(H).56` 行，很可能是**从 `6006FBC1` 复制而来**的
（工艺卡的"复制其他工艺"功能正是本项目的 `state_copy` 操作所对应的车间行为）。

### 6.3 模板导出的源图号与实际测试图纸**不一致**

模板 `route_templates_v1.json` 声明来源是：

```
dataset/BJ/excel/工序选择.xlsx (D106NW1(H).56) + dataset/config/保持架/D109/
```

但实际测试数据里的图是 **`D106NKW1(H).56`**（`E:\AAhz\测试数据\椭圆\D106NKW1(H).56.dwg`），
多一个 `K`。全部署扫描确认：

```
D106NKW1(H).56   (not found anywhere)
D106NW1(H).56    28 + 24 + 28 rows (三份表都有)
```

**`D106NKW1(H).56` 在任何路线表里都不存在**，它只能靠 `D106NW1(H).56` 的路线
（或者类别模板）来覆盖。这就是注册表里 `D106NKW1(H).56` 只有 `template_category`
而没有 `excel_exact` 的原因——**不是上游行失效了，而是图号对不上**。

而 `D106NKW1(H).56` 的图纸技术要求明确写着：

```
1. 锻件投料，锻件类别：Ⅲ类，锻件质量应符合ZZT02-HT-013的规定。
4. 保持架需调质处理，处理后的质量应符合ZZT02-HT-007的规定，调质后硬度为33～37HRC。
```

**锻件投料 → 不该有下料/锻造；需调质 → 工序该叫 `调质` 不该叫 `热处理`。**
而我们给它的模板（28 道）恰好是**两个都不对**的那一版。

### 6.4 结论

模板证据链断在两个地方：

1. **版本选错**：模板导出时取的是 `20260918`/`NOVbcj` 版的 28 道路线，
   而不是 `20260917` 版的 24 道。**证据链上唯一与车间实际（`6006FBC1`）逐道一致的
   恰好是 20260917 版**，模板却没用它。
2. **图号错配**：模板源图号 `D106NW1(H).56` ≠ 实际图纸 `D106NKW1(H).56`。

**修正方向明确**：以 `6006FBC1`（excel + card 双源印证、24 道、与 20260917 D106 逐道一致）
作为保持架路线的基准，按以下三条规则条件化：

| 规则 | 依据 | 效果 |
|---|---|---|
| 有 `锻件投料` → **删除** 4 道备料段 | 图纸技术要求第 1 条 | 28 → 24 |
| 技术要求写"调质" → 工序名用 **`调质`** | 图纸技术要求第 4 条 | `热处理` → `调质` |
| 兜孔用 `pocket_radius` → 椭圆类 | 图纸几何 | 区分正圆/椭圆变体 |

**这三条全部可由图纸证据自动判定**，不需要人工。
做完之后，"类别路线"就升级为**证据驱动的条件化路线模板**，
那才是论文 §3.8 真正值得写的贡献——而且它本身就演示了
"设计要求 → 工艺路线"的对齐过程，正是本文主题。

### 6.6 建议的下一步

1. **优先**：把 `card_exact` 的 3 个案例与 `excel_exact` 的 1 个案例重新定性，
   并决定是否用不完整 card 路线覆盖了本该用模板的案例。
2. **优先**：按 §6.4 的三条规则实现条件化路线模板。
   规则全部可由图纸证据自动判定，做完后模板证据链才闭合。
3. **然后**：核实 `D106NKW1(H).56` 与 `D106NW1(H).56` 是否为同一零件的不同版本，
   若是，则模板源图号应改写为后者并注明版本依据。
4. **然后**：用条件化模板重建 24 个保持架案例的 `target`，
   路线变化会导致词表变化，需要重跑划分闭包检查与训练。
